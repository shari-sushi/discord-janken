# タイマー機能外部ツール選定

## 要件

### 機能要件

- 秒単位の精度
  - 理想: 1s以内
  - 現実的な許容範囲: 5s以内
  - 妥協点: 30s以内
- リクエスト数
  - 理想: 500req/days 以上
  - 現実的な許容範囲: 75req/days 以上
  - 妥協点: 30req/days 以上

※妥協点となった場合はAPIを公開せずに、身内のみで使用

### 技術的制約

- Discord Interactionの3秒制限（即座に応答が必要）
- Vercelのサーバーレス環境（常駐プロセス不可）
- 既存技術スタック: Next.js, Redis, Vercel

## 検討したソリューション

### 1. Vercel Cron

#### 概要

Vercel標準のCron Job機能

#### 実行頻度制限

- **Hobby（無料）プラン**: 最小 **1時間**（3,600秒）
- **Pro/Enterprise プラン**: 最小 **1分**（60秒）
- **サブ分（60秒未満）スケジューリング**: **全プランで不可能**

#### 評価

| 項目 | 評価 | 詳細 |
|------|------|------|
| **精度** | ❌ | 最小60秒（妥協点の30秒も満たさない） |
| **リクエスト数** | ✅ | 制限なし（理想を満たす） |
| **実装複雑度** | ✅ | 低 |
| **追加コスト** | ✅ | 無料 |

**結論**: ❌ **要件を満たさない**（精度要件を満たせない）

- [Vercel Cron Jobs - Usage & Pricing](https://vercel.com/docs/cron-jobs/usage-and-pricing)

### 2. Upstash QStash

#### 概要

HTTPベースのメッセージキューサービス。遅延実行・スケジュール実行に対応。

#### 実行精度

- ✅ **秒単位のスケジューリング対応**
- ✅ 遅延実行（`delay`）で秒単位指定可能
- 実際の精度: **1〜5秒程度**（ドキュメント未明記だが、一般的なキューサービスの精度）

#### アーキテクチャ

```text
[Discord] → [/lol-timer] → [QStash Publish]
                ↓              (遅延実行を指定)
        即座に「設定完了」応答
                               ↓
                         指定時刻にQStashが
                         コールバックURLを呼び出し
                               ↓
                    [Discord Webhook送信]
```

#### 実装例

```typescript
import { Client } from "@upstash/qstash";

const client = new Client({ token: process.env.QSTASH_TOKEN });

await client.publishJSON({
  url: "https://your-app.vercel.app/api/timer/execute",
  body: {
    channelId: "123456789",
    message: "時間です！"
  },
  delay: 300 // 300秒後（5分後）
});
```

#### 料金プラン

| プラン | リクエスト数/日 | 月額 |
|--------|----------------|------|
| **Free** | 500 | $0 |
| **Pay as you go** | 無制限 | $1 per 100k |

#### 評価

| 項目 | 評価 | 詳細 |
|------|------|------|
| **精度** | ✅ | 1〜5秒程度（現実的な許容範囲を満たす） |
| **リクエスト数** | ⚠️ | 無料: 500/日（理想の"over 500"には届かないが近い） |
| **実装複雑度** | ✅ | 低 |
| **追加インフラ** | ✅ | 不要 |
| **追加コスト** | ✅ | $0〜（有料プランで無制限化可能） |

**結論**: ✅ **推奨**（精度・リクエスト数ともに十分）

#### 参考

- [Upstash QStash Documentation](https://upstash.com/docs/qstash)

### 3. Redis Keyspace Notifications

#### 概要

RedisのKeyspace Notifications機能を使い、キーのEXPIREイベントを検知してタイマーを実装。

#### 実行精度

- ✅ **リアルタイム（1秒以内）**
- ✅ 最も高精度（理想を満たす）

#### アーキテクチャ

```text
[Discord] → [/lol-timer] → [Redis SET with EXPIRE]
                ↓
        即座に「設定完了」応答

[外部Worker (Railway/Fly.io等)]
    ↓ 常時接続
[Redis Keyspace Notifications]
    ↓ EXPIREイベント検知
[Discord Webhook送信]
```

#### 必要な構成

1. **Redis設定変更**: `notify-keyspace-events Ex` を有効化
2. **外部Workerデプロイ**: Railway / Fly.io / Render.com など
3. **Worker実装**: Node.jsでRedis Pub/Subを監視

#### 料金

- **Railway**: $5/月〜
- **Fly.io**: 無料枠あり（制限付き）

#### 評価

| 項目 | 評価 | 詳細 |
|------|------|------|
| **精度** | ✅✅ | 1秒以内（理想を満たす） |
| **リクエスト数** | ✅✅ | 無制限（理想を超える） |
| **実装複雑度** | ❌ | 高 |
| **追加インフラ** | ❌ | 必要（外部Worker） |
| **追加コスト** | ❌ | $5/月〜 |

**結論**: ⚠️ **高精度・高リクエスト数が必要な場合に検討**

## 選定結果

### 採用: **Upstash QStash**

#### 理由

1. ✅ **精度要件を満たす**: 1〜5秒程度（現実的な許容範囲内）
2. ✅ **リクエスト数要件を満たす**: 500/日（現実的な許容範囲75/日を大きく超える）
3. ✅ **実装が簡単**: HTTPベースで直感的
4. ✅ **追加インフラ不要**: Vercel内で完結
5. ✅ **公式統合**: Vercel Marketplaceで公式サポート
6. ✅ **ドキュメント充実**: 実装例が豊富
7. ✅ **スケーラブル**: 有料プランで無制限にアップグレード可能

#### リクエスト数について

要件では「理想: over 500req/days」とありますが、無料プランの500req/dayでも：

- **現実的な許容範囲（75req/day）を6.6倍超える**
- 身内で使う場合は十分すぎる余裕
- 必要に応じて有料プラン（$1 per 100k）で無制限化可能

#### 代替候補

リクエスト数が500/日を大きく超える見込みがある場合：

1. **Inngest**（無料で166/日、$20/月で無制限）
2. **Redis Keyspace Notifications**（無制限だが実装コスト高）

## 実装上の注意点

### QStash使用時

1. **署名検証必須**: セキュリティのため、QStashからのリクエストを検証
2. **タイムゾーン変換**: JST→UTCの変換処理が必要
3. **エラーハンドリング**: QStash登録失敗時の処理
4. **使用量監視**: 500リクエスト/日の上限を監視

### セキュリティ

- QStashコールバックエンドポイントは公開URLなので、署名検証は必須
- Discord Webhook URLは環境変数で管理

### 将来的な拡張性

- 500req/日を超える場合 → 有料プラン（$1 per 100k）にアップグレード
- より高精度が必要な場合 → Redis Keyspace Notificationsへの移行を検討
