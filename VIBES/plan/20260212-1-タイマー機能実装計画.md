# タイマー機能実装計画

## 概要

Discord Botにタイマー機能を追加する。ユーザーが指定した時刻（HH:MM形式または「M分後」）に、Botがチャンネルにメッセージを投稿する。

## データ構造

### QStash送信データ

```typescript
{
  channelId: string;      // 通知先チャンネルID
  message: string;        // 通知メッセージ
  guildId: string;        // サーバーID
  createdBy: string;      // 設定したユーザーID
}
```

## 想定ユーザーフロー

1. ユーザーが `/lol-timer` を実行
2. モーダルが表示（時刻入力フォーム、メッセージ入力フォーム）
3. ユーザーが時刻とメッセージを入力して送信
4. Botが即座に「タイマーを設定しました」と応答
5. 指定時刻にBotがチャンネルにメッセージを投稿

## アーキテクチャ上の判断

### QStash → 自前APIコールバック → Discord Bot API という構成について

QStashからDiscord APIを直接呼ばず自前APIを挟んでいるのは意図的である

**QStashからDiscord APIを直接呼ぶ問題点:**

- QStashのリクエストにはカスタムヘッダーを付与できるが、そうすると `Authorization: Bot {TOKEN}` をUpstashのサーバーに渡すことになる
- Bot トークンは機密情報であり、サードパーティサービスに預けるべきではない

**自前コールバックAPIを挟む利点:**

- Bot トークンはサーバーサイドの環境変数に留まる（外部に漏れない）
- コールバック時にDBアクセスなど追加ロジックを実行できる（例: `reminder/route.ts` でのRedis確認）
- QStash署名検証により、正規のQStashからのリクエストのみ処理できる

## 注意事項

- QStashの無料プラン制限: 500リクエスト/日
- 時刻はJST→UTCに変換が必要（サーバーはUTCで動作するため `setUTCHours(hours - 9, ...)` を使用）
- QStashコールバックURLは公開エンドポイントである必要がある
- QStash署名検証を必ず実装する（セキュリティ対策）
