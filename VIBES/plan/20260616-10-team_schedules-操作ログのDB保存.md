# team_schedules: ログデータを DB に残す

> 元 issue: [#107](https://github.com/shari-sushi/discord-janken/issues/107)
> ⚠️ 本計画は暫定。仕様は 2026-06-17 に作者と確定する。費用対効果の判断が必要。

## 目的・背景

> - 誰が誰を招待したかわかるようにする
> - 誰がチーム設定を変更したかログを残す...? ←嵐対策にと思ったけど実装とdbが重い割に得られるもの小さすぎるかも

操作の監査ログを DB に残す。ただし issue 本文どおり、**実装/DB コストの割にリターンが小さい懸念**があり、やる範囲を絞る前提。

## 実装方針（案・最小スコープ）

優先度を分けて検討:

- **高（軽い・価値あり）**: 招待の発行・使用ログ（誰が誰を招待したか）。`#108`（招待リンク管理）でトークンに `invitedBy` を持たせるので、その延長で記録できる。
- **低（重い・価値小）**: チーム設定変更の全般的な監査ログ。汎用 `audit_logs` テーブルを切るとコスト増。

### 最小案

- 招待まわりだけログ化（join 成立時に「inviterUserId / inviteeUserId / teamId / joinedAt」を残す）
- 汎用監査ログは見送り or 将来拡張

### フル案（必要なら）

- `audit_logs`（teamId, actorUserId, action, target, payload(jsonb), createdAt）テーブルを新設し、書き込み系 API から記録
