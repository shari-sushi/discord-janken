# 実行計画書のルール

## ディレクトリ構成

| ディレクトリ  | 用途                                     |
| ------------- | ---------------------------------------- |
| `VIBES/plan/` | 実行計画書（作業前に作成し               |
| `VIBES/wip/`  | 作業中メモ・調査メモ。実行計画書とは別。 |
| `VIBES/done/` | 完了した実行計画書の保管場所             |

## 命名規則

- `YYYYMMDD-{その日付の何個目か}-{日本語で簡単な作業内容}.md`
- wipの命名がどのplanを示しているかが分かる必要は無い。

**例:**

- `20260208-1-Redisリファクタ.md`
- `20260208-2-フィードバック機能修正.md`

## ライフサイクル

1. 作業開始前に `VIBES/plan/` にファイルを作成
1. 作業を一時中断する際は `VIBES/wip/` にもファイルを作成
1. 作業が完了したら実行計画書は `VIBES/done/` に移動し、wip書は削除する
   - `git mv VIBES/plan/ファイル名.md VIBES/done/ファイル名.md`

なお、必要に応じて、作業中の調査結果を実行計画書に追記する。
また、実行計画書は必ずある必要は無く、軽度作業ではwipのみで完結しても良い。
(その際、必要に応じて`VIBES/done/`, `VIBES/plan/`を修正/加筆する)
